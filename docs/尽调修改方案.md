## 二、目标权限结构

```text
Cactus Governor 钱包（proposer + executor，保留标准取消权）
    → 标准 TimelockController（初始 7 天，self-admin）
    → GovernanceController（原协议唯一 Governor）
    → 原协议显式管理入口

Cactus Guardian 钱包 → 标准 TimelockController.cancel
```

以上是待部署及移交后应达到的结构，不代表当前链上已完成切换。

- 初始 proposer 和 executor 使用同一现有 Cactus 钱包，不配置开放执行人 `address(0)`。
- Cactus 在此作为具备链上签名能力的钱包；人员审批仍依赖其既有流程，不能据此称为链上多签。
- 时间锁构造时 `admin=address(0)`，仅时间锁自身持有管理员权限，没有额外外部管理员。
- Guardian 通过正常延迟的时间锁自调用取得 `CANCELLER_ROLE`，可取消未执行操作，不能提前执行、回滚已执行操作或触发新增紧急功能。
- 7 天是初始等待期，不是永久硬底线。标准 `updateDelay` 只能由时间锁自调用，修改操作本身须先遵守当时的等待期；角色管理也遵守标准自管理流程。
- Governor 只能由 Controller 持有；时间锁和人员钱包不直接持有该角色。其唯一性须通过实际角色移交核验，不能由部署 Controller 自动保证。

## 三、Controller 的职责与边界

所有修改状态的入口均要求调用者为固定时间锁。协议目标地址固定，采用显式函数转发，没有通用任意 `call`、`delegatecall`、fallback 或任意授权入口。

转发范围涵盖原 Governor 的 Pool 转账、准入及升级、StateManager 模块配置、协议费用、收入池提款及费源、桥接准入、Vault 协议分费，以及 ReservePSM 既有管理操作。现有模块／PSM 暂停操作同样等待时间锁，不构成新增快速处置机制。

可选 Oracle Owner 管理须同时满足：Oracle 已列入 `managedOracles`，且其实际 `owner()` 为 Controller。登记名单不自动移交所有权；该层不代理 `updateNAV`，不修改价格算法或 Adapter 绑定。

ReservePSM 新建包装资产会把 Controller 记为 `controllerOf`，专用路由保留这些资产的签名人和暂停管理能力。历史包装资产的 Controller 不自动改变。

`migrateGovernor` 仅按预期 runtime code hash 核验继任合约，在同一交易先授新 Governor、再撤销本合约角色。代码哈希不证明继任合约安全；Oracle Owner 须另行移交。原 PSM 没有转移 `controllerOf` 的入口，因此本 Controller 创建过包装资产后，后续仍须保留旧 Controller 和旧时间锁的可操作性。

Vault Owner、Curator、Allocator、Guardian、Keeper、Settlement Operator 及其他独立资产权限不由本次代码自动接管。

## 四、部署工具与权限切换

部署脚本是链下 Foundry 工具，读取公开配置并先核对原合约绑定。它仅准备部署标准时间锁和 Controller；是否广播由调用方另行选择和签名。脚本不读取私钥，不自动授予／撤销 Governor，不移交 Oracle Owner，也不更改原协议配置；输出的后续管理交易数据不等于交易已执行。

建议按以下顺序交接：

1. 逐链确认 chainId、原合约地址、代码和依赖绑定，核对 Governor 完整历史及各 Oracle／包装资产管理身份，保留当前可用权限。
2. 完成本地验证及所需审计、上线决策后，另行部署新时间锁和 Controller，验证成功回执、实际代码及构造配置。
3. 通过标准时间锁排队并执行 Guardian 取消权配置，再核验 proposer、executor、canceller 和 self-admin。
4. 原 Governor 授权 Controller，验证实际延迟调用路径；此时尚不能认定移交完成。
5. 从原 ACL 部署块起按顺序重放 `RoleGranted/RoleRevoked`，并核验各地址 `hasRole`，撤销／放弃全部旧 Governor，确认 Controller 为唯一持有人。
6. 如将 Oracle Owner 纳入本次交接，逐实例完成名单登记和实际所有权移交，再核验双条件；不得假定 Governor 切换会同时完成这些操作。
7. 更新调用方和运营记录，保存部署、角色变化及实际时间锁配置证明。

不得先撤旧再授新。钱包的多笔授权／撤销不自动具有原子性；模拟、编译或本地测试均不能代替链上回执。

## 五、本轮三项小修复

1. 部署预检对 StateManager 使用实际 `accessControl()`，其他模块继续使用各自的 `ac()`，修复原脚本接口不匹配导致的回退。
2. Bridge 新增白名单仍检查注册；撤销仅禁止零地址，允许清理历史未注册条目，仍须遵守时间锁。
3. 配置 RevenuePool 时，部署前检查其 `usdt()` 与 UnifiedPool 一致；该检查不限制 Bridge 的其他币种配置，不修改原合约参数。
